## 最新進捗（2026-10-31）

VRモードで、らいがフルトラッキングの全身を自分で動かせるようになりました。全身の動きは、公開されている人間動作の生成モデルを土台にした独自の身体エンジンが、その場で生成しています。身体エンジンの構成と参考にしたものは、別紙 [BODY_ENGINE.md](BODY_ENGINE.md) にまとめています（エンジン本体のコードやモデルは公開しません）。

- VRモードの通常起動で、フルトラッキングの自動キャリブレーション、身体エンジンの起動、AIへの身体の引き渡しまでを人の操作なしで行います。操作パネルは「AIに任せる」「止める」「自分で動かす」「ワールド移動」の4つにまとめました
- 「座って」「寝転んで」「起きて」「踊って」「右を向いて」「ジャンプして」などの音声指示を、固定アニメーションの再生ではなく、身体エンジンの全身生成として実行します。「ついてきて」は、身体エンジンが立ち姿勢を保ったまま、スティック入力とVRChatのフルトラッキング移動で相手を追います
- 「10秒手を振って」のような秒数指定、「5秒後に手を振って」のような時刻指定、「人が見えたら手を振って」のような条件指定、「やめて」での停止と予約の取り消しに対応しました
- 「猫の真似して」のような一覧にある真似に加えて、一覧にない真似（「宇宙人の真似して」など）は、会話側のモデルが動作の説明文を書き、身体エンジンがそれを条件に動きを生成します（設定で有効化）
- じゃんけんは、相手の掛け声の「ぽん」に合わせて手の形（グー・チョキ・パー）を出し、指の形を相手から見える向きで示します
- 体の頼みへの採用・断り・取り消しと返事を連動させ、実際の動作と発言の食い違いを減らすようにしました
- 会話側では、相手が話し終えたかの判定と宛先の推定、「しばらく黙ってて」の期間付きの静かなモード、複数人の声を話者ごとのトラックに分ける処理（設定で有効化）を追加しました
- 会話の品質では、似た返事の繰り返しを減らす調整、過去の会話との整合性を評価する記録、返事が無かった回も相手の言葉を覚えておく処理を追加しました
- ユーザー定義ルール（15章）は、現在の会話・身体の機能と重複するため既定で停止しています

## 概要

VRChat上で動作する、音声会話・視覚認識・長期記憶・感情/欲求モデル・自律行動・OSCによる身体制御を組み合わせたAIエージェントです。

ユーザーの声を聞き、周囲をカメラで認識し、ローカルまたはクラウドAPIを使って会話します。返答はローカルTTSとVRChat Chatboxで出力し、視界説明や検索には外部サービスも利用します。会話モデルの選定や内部構成は非公開です。

VRChat OSCとキーボード入力を使い、アバターの移動、視線、表情、エモート、Use/Grab、ピアノ演奏などを制御します。VRモードでは、独自の身体エンジンが生成した全身の動きを仮想トラッカーへ送り、フルトラッキングのアバターを動かします（33章、別紙 [BODY_ENGINE.md](BODY_ENGINE.md)）。

会話面で目指しているのは、質問に正確に答えるアシスタントではなく、話していて面白いキャラクターです。賢さより、その場の反応、言い切り、脱線、こだわりが続くことを優先しています。

単純なチャットボットではなく、会話相手、視界内の人物や物体、なでられた状態、現在の感情、退屈さ、疲れ、孤独、好奇心、反発、過去の記憶、相手との関係性などを内部状態として持ちます。状況に応じて、話す、見る、歩く、止まる、探す、反応する、待つ、遊ぶ、ピアノを弾くといった行動を選びます。

## できること

### 1. 音声で会話する

- マイク/仮想オーディオ入力からユーザーの声を取得
- ストリーミング音声認識で、日本語の話の切れ目を捉える
- 主経路が使えない場合に備えた音声認識の予備経路を持つ
- 音声認識の誤りを減らし、聞き取りが不確かな時は聞き返す
- 「うん」「まじで」「なるほど」のような短い相槌にも反応する
- 会話に出てきた固有名詞を聞き取りやすくする
- リアルタイムVADで「ユーザーがまだ話している途中」を判定
- ユーザーの発話中は返答を待ち、割り込み/停止指示も処理
- 自分の再生音の回り込みと、相手の割り込みを区別する処理を持つ
- 相槌程度の被せでは発話を止めず、表情とうなずきだけで受け止める
- 話しかけられた内容や状況に応じて、返答や相槌、聞くだけの反応を選ぶ
- 条件を満たす会話では、返答がすべてできる前から句切りごとに話し始める
- 一言、長話、脱線など、キャラクターの返答に幅を残す
- 録音長と待ち時間を分けて計測し、削れる遅延と発話そのものの長さを区別してログへ出す

### 2. 話者を識別する

- 登録済みのマスター音声と発話を照合
- 登録済みの主人、初めて聞く相手、識別できなかった声を区別
- アバター側に用意した、主人が話しているかを示すOSCパラメータも参照
- 知らない人の発話は内容に応じて即返答/保留を判断
- 複数人との会話でも、話者を区別して追跡する
- 発話者に応じて距離感、警戒、返答の優先度を変える

### 3. VRChatアバターを操作する

- Chatbox送信
- 前後/左右の移動入力、停止、旋回
- 視線の水平・垂直操作
- ジャンプ、連続ジャンプ
- 座る、寝転がる、立ち上がる
- 手を振る、拍手、指差し、応援
- ダンス、バックフリップ、倒れる系リアクション
- Use
- Grab
- Grab Hold
- Drop/Release
- 表情変更
  - neutral
  - calm
  - blush
  - smug
  - sad
  - puzzled
  - smile
  - happy
  - joy
  - angry
  - fear
  - surprised
  - troubled
  - tongue
  - wink
- アバター内ピアノの表示/非表示、着席、鍵盤パラメータ操作
- 左右のマラカス表示、発音、逆位相の腕振り

VRモード（フルトラッキング）では、上の操作のうち姿勢・身振り・移動を、仮想トラッカーへ送る全身の姿勢として実行します。

- 頭・両手・腰・両足の6点を、身体エンジンが生成した全身の動きから毎フレーム送る
- 立つ、座る、しゃがむ、寝転ぶ、起き上がる
- 手を振る（右・左・両手、座ったままも）、拍手、指差し、応援、お辞儀、うなずき、首を振る、伸び、ポーズ
- 踊る（秒数指定・続けて踊る）、感情を全身で表す（喜び・考え込む など）
- 歩く（前後左右、半径1.2mの範囲）、向きを変える（速さ3段階）、ジャンプ（回数指定）
- 動物や人物の真似、匍匐前進
- 指の形（グー・チョキ・パー・ピース）
- 「ついてきて」での追従（スティック入力とVRChatのフルトラッキング移動）
- マラカス・ピアノ・炎は、全身の動きと競合しないように制御する
- 会話中は、話す・聞く・考える・黙るに合わせた姿勢へ身体エンジンが切り替える

### 4. 炎ギミックを制御する

VRChatアバター側の炎制御OSCパラメータを使い、アバターの炎・火炎放射系ギミックを制御します。

炎ギミックには、ユーザーからの直接命令と、感情状態に応じた自動発火があります。
「火炎放射」「火を吹いて」「fire」「flame」などの発話を検出すると、短時間だけ炎を出し、自動でOFFに戻します。「火を消して」「炎止めて」「stopfire」など炎に関係する停止発話では即座にOFFへ切り替えます。

感情連動では、怒り、得意げ、喜び、驚きなどに応じて炎の演出が変わります。自律行動中に気まぐれで発火することもあります。

一方で、悲しみ、恐怖、罪悪感が強い時は、演出が不自然にならないよう感情連動の炎を抑制します。ピアノ演奏中やピアノ操作ロック中も、演奏の邪魔をしないよう感情連動・自律発火の炎を止めます。

追加演出として、「怪獣になって」「怪獣モード起動」などの発話で、一定時間だけ移動、視線、ジャンプ、炎を組み合わせるランページ動作も持っています。ピアノ演奏中は発動しません。

### 5. ユーザーの指示を理解して行動する

音声で以下のような動作を頼めます。返事と身体動作を連動させます。

- 「座って」: 座る
- 「寝転がって」: 寝る
- 「立って」: 立つ
- 「ついてきて」: ユーザーを追従
- 「止まって」: 移動停止
- 「右/左を向いて」: 旋回
- 「手を振って」: wave
- 「踊って」: dance
- 「これ見て」: 視覚認識
- 「使って/押して/開けて」: Use
- 「持って/掴んで」: Grab
- 「持ったままにして」: Grab Hold
- 「離して」: Release
- 「ピアノ出して/しまって/弾いて」: ピアノ表示、非表示、演奏
- 「マラカス振ろうよ」「アミーゴしよーぜ」: マラカス演奏

単に話題として「マラカス」と言っただけでは演奏せず、振る、遊ぶなどの実行意図がある時だけ明示指示として扱います。

VRモードでは、次の言い方にも対応しています。

- 「10秒手を振って」「20秒踊って」: 動作の続く時間を指定する（1〜60秒。範囲外や、歩く・向きを変えるなど秒数の意味が合わない動作は返事の前に断る）
- 「5秒後に手を振って」: 時刻を指定して予約する。「やめて」で予約を取り消す。「やっぱり20秒後にして」で時刻を変える
- 「人が見えたら手を振って」: 条件を満たした時に実行する。自分の姿（自分を映す鏡やカメラの像）は人として数えない
- 「起きて手を振って」「座って右手を振って」: 先に姿勢を変えてから動作する
- 「猫の真似して」「宇宙人の真似して」: 一覧にある真似は登録済みの動作で、一覧にない真似は説明文からの生成で動く（後者は設定で有効化）
- 「じゃんけんしよう」: 相手の掛け声に合わせて手を出す
- 「しばらく黙ってて」「5分黙ってて」「もう喋っていいよ」: 期間付きの静かなモードと解除
- 「止まって」「やめて」: 実行中の動作を止める

### 6. 視覚で周囲を認識する

- カメラ入力（OBSを使う場合は仮想カメラを含む）からフレームを取得
- 人物・姿勢検出で人物検出
- 複数人物の検出
- 人物の位置、面積、画面内中心を推定
- ユーザーとの距離感をざっくり推定
- 視界に人が入った/消えたことを検知
- 肩、腰、手首などのキーポイントを取得
- 手振り、しゃがみ、急な動きなどを検出
- VLMで画像を説明し、「これ見て」のような依頼に返答
- 明示的な視覚質問では外部APIのVLMを優先して現在フレームを説明
- ローカルVLMの補助は追加機能として持つ（現在の実機設定では無効）
- 複数の視覚情報を照合し、人物や物体の誤認を減らす
- 外の視界と自アバターの映像を区別し、自分を会話相手や追従対象として扱わないようにする。入力映像の役割や自アバターの領域は運用者が設定する
- 会話を邪魔しない範囲で、気分や周囲の状況に応じて自分から視界を確認する
- 手元の画像を切り出し、相手が見せている物や持っている物を確認する
- 手元の確認にも外部視覚APIと、追加設定によるローカル補助を利用できる

### 7. カスタム物体検出で特定オブジェクトを検出する

- 学習済みカスタム物体検出でVRChat内の特定オブジェクトを検出
- 現在の有効対象
  - ドアノブ
  - ポテトチップス系オブジェクト
- ドアノブを見つけると向きを合わせ、必要に応じてジャンプ+Use
- ポテトチップス系オブジェクトなど、持てる/触れる対象に対してGrab/Use系の反応
- 検出信頼度、画面内位置、クールダウンを考慮
- 同じ物体に反応しすぎないように制限
- 人物追従と物体注視が干渉しないよう、人物ターゲットと物体ターゲットを分離
- 人物・姿勢検出と、対象を絞ったカスタム物体検出を組み合わせる
- 実際の接近、視線調整、Use/GrabはOSC操作シーケンス側で実行

### 8. 深度推定で歩行を補助する

- 単眼深度推定で単眼カメラから相対深度マップを推定
- 画面を左/中央/右、床/中段などのゾーンに分けて解析
- 前方が通れるか、障害物が近いかを判定
- 左右どちらが空いているかを推定
- 壁沿いの移動や袋小路からの回避を補助する
- 深度が古い/取得できない場合は通常の視覚情報と安全寄りの移動にフォールバック
- デバッグ用に深度オーバーレイ表示が可能

### 9. ユーザーを追従する

- 視界内の人物をターゲットとして追う
- 近すぎる場合は停止
- 遠い場合は前進
- 画面中央からのズレに応じて向きを調整
- 見失った場合は最後に見えた方向を探す
- しばらく見失うと探索行動へ移行
- 追従中も視線・身体向き・距離を別々に調整
- 追従開始時の見た目情報を使い、対象の取り違えを減らす

### 10. 自律的に行動する

会話や命令がない間も、気分、好奇心、周囲の変化、未完了の話題などに応じて、自分から話したり動いたりします。

- 周囲を見回す、散歩する、興味のあるものへ近づく
- 疲れたら座る・休む、眠そうな時は寝転ぶ
- 相手の接近や、見失ったことに反応する
- 気分に応じてピアノやマラカスで遊ぶ
- 拾い残した話や、自分が気になっている話を始める
- 話す理由がなければ黙っている

自律発話は固定の台詞を順番に読むものではありません。短い独り言、長めの話、問いかけなどに幅を持たせ、言い回しはその場で生成します。相手との会話を妨げないよう、自発的な発言や行動の頻度も調整しています。

### 11. 感情・欲求・性格傾向を持つ

喜び、愛着、怒り、悲しみ、恐怖、罪悪感などの感情と、疲れ、孤独、退屈、好奇心、反発などの欲求を持たせています。これらは返答のトーン、表情、移動、休憩、自律行動、頼みへの反応に影響します。

なでられて機嫌が変わる、演奏をした後に気分が変わる、といった変化もあります。同じ出来事でも直前の気分で反応が変わり、一つの感情だけで行動が決まるわけではありません。通常の性格と、毒気や身勝手さを強めた性格を切り替える機能もあります。

**感情を声色に乗せる**

話者スタイルの切り替えに加え、話速、音高、抑揚、音量を調整し、怒り、沈み、驚きなどを声でも表します。同じ感情でも少しずつ違う話し方になるようにし、別人の声に聞こえるほどの変化は抑えています。専用の感情音声モデルを学習したものではありません。

### 12. なでなでに反応する

- アバター側で、頭をなでられたことを検出する
- なでられている間、表情や感情が変化する
- 親しさ、機嫌、寂しさなどにも影響する
- なでられたことに反応し、ほかの行動を中断する場面がある

なでられたことの検出には誤りがあり、入力の調整や実機確認が必要です。

### 13. 長期記憶と短期文脈を持つ

会話の内容、相手の好み、関係性、実際に起きた出来事を記録し、後の会話で思い出せるようにしています。直近の会話と長期の記録を使い、答えそびれた話を自分から拾い直したり、以前ウケた話にもう一度触れたりします。

- 誰がいつ話したことかを区別し、相手の発言を自分の属性と取り違えないようにする
- 自分が何かを言ったことと、その内容が事実であることを区別する
- 中断された会話も、記録できた発言と中断の事実を残す
- 思い出した出来事の感情や印象が、現在の反応にも影響する
- 該当する記憶がなければ、無理に思い出したことにしない

記憶は完全ではありません。必要な出来事を取りこぼしたり、似た話を取り違えたりする可能性があります。過去の記録には復元できない中断会話もあり、その件数は不明です。記録がないことを、出来事がなかった証明にはしません。

記憶の利用状況は、取得件数、会話で使えた件数、処理の期限切れなどを分けて確認しています。点検・整理の際は、削除候補の確認とバックアップを行います。整理の判断にも誤りがあり得るため、自動で完全に正しい記憶になるとは扱いません。

### 14. 関係性を更新する

会話、なでなで、接近などの出来事から、相手ごとの親しさ、信頼、愛着、警戒を変化させます。その印象を後の返答や距離感、行動にも反映します。すべての相手へ同じ態度を取るのではなく、関係が続くことで接し方が変わることを目指しています。

### 15. ルールを覚える

> 2026-10現在、この旧機能は既定で停止しています。一時的な指示を継続的なルールと誤って記録する問題が実機で確認されたためです。現在の条件つき動作は35章、停止や静かなモードは37章を参照してください。

旧機能では、特定の場面での行動を覚え、確認、追加、取り消し、忘却を行えます。以下は有効にした場合の例です。

- 人が見えたら手を振る
- なでられたら特定の表情にする
- 鏡の前で特定の行動をする
- 操作できる物を見つけたら使う

頼みをいつでも従順に実行することを、キャラクターの目標にはしていません。

### 16. 視線を自然に動かす

- 会話相手や興味のある物へ視線を向ける
- 凝視し続けず、視線を外したり小さく揺らしたりする
- 興味や退屈さによって視線の動きが変化する
- 相手を見失った方向を探す

人物と物体の見分けや視線合わせは、カメラの認識精度と画角に影響されます。

### 17. 鏡・自分の姿に反応する

鏡や自分の姿を探し、見つけたものに表情や言葉で反応する機能があります。画像認識の補助を有効にした場合は、自分や鏡像らしいかの判定も使います。反応の言い回しはその場で生成します。

自己と他者の判定は確実ではありません。画角や映り方による誤認があり、すべてのワールドや鏡で正しく認識できるわけではありません。

### 18. 物体・姿勢に反応する

食べ物、動物、家具、電子機器などを見つけ、興味に応じて見る、近づく、使う、持つといった反応をします。人物の手振り、しゃがみ、急な動きや、手元で見せられた物にも反応します。

表情だけでなく、時々言葉でも反応します。同じ対象へ反応し続けたり、会話へ頻繁に割り込んだりしないよう調整しています。物の種類や姿勢の認識には誤りがあり、実際の操作は起動モードと対象物の対応状況に依存します。

### 19. ピアノを弾く

- アバター内のピアノを表示・非表示にする
- 88鍵ぶんのOSC操作で、MIDI曲やアバター向けの譜面を演奏する
- 演奏の頼みや曲の指定を受ける
- テンポ、サステイン、同じ音の重なりなどをアバターの鍵盤仕様に合わせる
- 気分に応じた即興フレーズを作り、保存して後から再演奏する
- 演奏中はほかの身体操作との競合を抑え、停止の頼みに応じる

演奏の確認では、送った鍵盤操作とVRChatから返った反応を比べ、音抜けの候補、余分な反応、タイミング誤差、テンポのずれを計測します。追加機能として、観測に基づく補正や調整済み譜面の保存にも対応しています。

VRChatからのOSC応答は、実際に鳴った音の録音検証ではありません。外部MIDI入力を使った検証にも対応していますが、VRChatの標準機能として実音がMIDIで返るわけではありません。アバターの鍵盤仕様、OSC負荷、同期状態により、演奏が欠けたりずれたりすることがあります。

### 20. 会話品質を安定させる

会話の内容だけでなく、声や字幕として届くまでを含めて品質を確認しています。

- 文字化け、内部の制御文の漏れ、同じ返答の反復を抑える
- 自律発話で、見えていない相手や状況を事実として語る誤反応を抑える
- 人物が見えたことだけで、その名前や話者を決めつけない
- 相手の発話を優先し、古い返事や自律発話が割り込まないようにする
- 待ち時間が長い時は、考え中であることを字幕で示す
- 強い拒絶や好意への返事も、その場の言葉として生成する

通常会話では、短い返事も長い話も内容に応じて出ることを重視し、意見や落ちを短文化だけのために切り捨てない方針です。独り言、物への反応、鏡への反応も、その場の言い回しを基本にしていますが、生成できない時に定型の言葉へ戻る場合があります。

これらは誤反応を減らすための処理であり、作り話や反復を完全に防げるという意味ではありません。毒、身勝手さ、自信満々の間違い、矛盾、脱線といったキャラクターの即興まで一律に消すことは目指していません。

「返答が毎回2〜3文で終わる」「同じ話を繰り返す」「見えていないものを話す」が同時に起きていた時期に、当時の8セッション・生成72回を調べました。

この集計は当時の構成の調査結果です。調整後の改善率や、現在の会話で同じ問題が起きないことを示す比較試験ではありません。会話の面白さは人が実際の発言を読んで評価し、知識の正確性、操作成功、遅延とは分けて扱います。

### 21. 知らない言葉を覚える

会話に出てきた未知の語やスラングを覚え、自分から使ってみたり、相手の訂正を受けて理解を変えたりする機能です。言葉を覚え、間違え、直される過程そのものを、会話の材料にすることを目指しています。

- 繰り返し聞いた言葉や、相手に教えられた使い方を記録する
- 必要に応じて外部情報も確かめる
- 同じ言葉でも、相手や会話によって意味が違うことを扱う
- 覚えた言葉を独り言でも試し、相手の反応を受けて理解を見直す
- 忘れるように頼まれた言葉の扱いを見直す

使うかどうか、訊くか、推測して話すかは、その場のキャラクターの振る舞いに委ねています。勝手に略したり、別の意味や造語として使い続けたりすることもあります。

語彙の理解や訂正の読み取りは完全ではありません。曖昧な訂正や音声認識の表記ゆれを取りこぼしたり、間違った意味のまま使ったりすることがあります。界隈ごとの用法を自動で判断する機能は未実装です。外部情報を取得できない時も、会話そのものは続けます。

### 22. Web検索・Wiki検索・視界検索を使い分ける

- 明示的な検索の頼み、百科事典的な質問、最新情報の質問、視界についての質問に対応する
- 百科事典的な情報にはWikimedia APIを使い、ニュース、価格、仕様、天気などは外部情報を調べる
- 視界についての質問では、その時のカメラ画像や認識結果を使う
- 検索の話題が続く間は、直前に調べた対象への追加質問にも対応する
- 検索結果やWikipedia本文をそのまま読み上げず、会話に合う言葉で返す

検索について話しただけで、必ず調べ始めるわけではありません。曖昧な依頼をどこまで判断できるかは、有効にしている機能と外部サービスの状態に依存します。話題の切り替わりを取り違えたり、検索先に情報がなかったりすることがあり、回答の正確性を保証するものではありません。

### 23. コア設計とモデルルーター

会話は、相手の発言、見えているもの、記憶、気分、身体の状態を組み合わせて作ります。返答を生成したこと、身体が実際に動いたこと、声や字幕として相手へ届いたことを区別し、生成しただけの内容を実行済みの出来事として扱わない方針です。

ローカルで会話するモードと外部APIを使うモードがあり、検索や視覚認識などの補助機能も組み合わせています。通信障害や利用制限によって、一部の機能や返答が利用できなくなることがあります。

会話モデルの選定、内部の判定・制御、プロンプトの構成、設定値は非公開です。

#### 生成した文が声になるまで

過去の実機では、生成できているのに声と字幕が出ない、長い返事の後半だけが届かない、といった失敗がありました。生成結果だけで成功とせず、実際に相手へ届いた範囲を調べて調整しています。

待ち時間や音声合成の所要時間は、返事の長さやPCの負荷、外部サービスの状態に影響されます。固定の応答速度や、長い発話が常に最後まで届くことを保証するものではありません。

### 24. 腕を自律的な身体表現として使う

> 24〜29章の腕の仕組み（Ude Group A・VGC）は、デスクトップモードの腕制御です。VRモードでは、腕を含む全身を身体エンジン（33章）が動かします。

会話、感情、周囲の人物や物体に応じて、撫でる、ハイタッチする、対象へ手を伸ばすなどの身体表現を行います。何もしないことも選びます。

実機で見た目を確認した動作を使い、成立していない握手やGrab系の腕動作は無効にしています。対象へ手を伸ばす動きには、使える腕や方向などの制限があります。

### 25. Ude Group Aで通常時の手遊びを作る

通常時の小さな手遊び、ためらい、左右非対称の揺れなど、アバターが硬直して見えないための背景表現に使います。

- 左右の腕を異なる形やタイミングで動かす
- 腕の位置が急に変わらないよう、滑らかに動かす
- 可動域は対象アバターの実機で確認した範囲に制限する
- 他の腕動作やピアノ演奏と競合しないようにする

### 26. VGC方向プリミティブから新しい動きを組み立てる

腕を上下左右や斜めへ動かす部品を組み合わせ、往復、上下運動、ためらって手を差し出す動きなどを作ります。速度や動きの大きさにも幅を持たせます。

撫でる、挨拶する、ハイタッチする、低い対象へ手を差し出すといった表現に使います。対象アバターに合わせた左右の対応や動作範囲の調整が必要です。

### 27. 相手の手・対象位置・接近を腕の目的へつなげる

相手が手を差し出したり上げたりしたことや、対象の位置を視覚から推定し、触れ返す、ためらう、何もしないといった反応へつなげます。

対象を見失ったり、届かなかったり、障害物があったりする場合は動作を中止します。自分の映像を他人として扱わないための区別も行います。姿勢の認識は遮蔽や画角に影響され、常に接触できることを保証する機能ではありません。

### 28. 腕の動作後を観察して結果を記憶する

腕を動かした後に、相手が近づいた、離れた、手を返した、見失ったといった変化を観察し、後の行動の参考にします。

判定は画面上の見え方による近似です。VRChat内部の正確な骨座標や、相手の意図を直接取得しているわけではありません。

### 29. 腕生成による会話への影響を抑える

会話や聞き取りを優先し、腕の判断や動作が返答を妨げにくいようにしています。外部サービスが使えない場合も、一部の腕の反応を続けられます。

会話への影響は実行環境に依存し、追加の遅延が常にゼロになることを保証するものではありません。腕の方向・速度・可動域は、実際のVRChat上でも確認します。

### 30. マラカスを振る

左右のマラカスを表示し、左右交互に腕を上下させて鳴らします。デスクトップモードでは腕ギミックを使い、VRモードでは全身の動きへ両手の専用動作を重ねます。

- 「マラカス振ろうよ」「アミーゴしよーぜ」などの誘いに応じる
- 自律行動として演奏することもある
- 喜び、孤独、退屈などに応じて演奏速度が変わる
- 演奏の結果が気分や欲求にも反映される
- ピアノや別の腕動作との競合を避け、終了時は小道具と腕を戻す

対象アバター固有の小道具と腕の設定を前提にした機能です。

### 31. Jevを限定的な中間スーパーバイザーとして使う

Jevは、検索や一部ギミックへの依頼の解釈を補助します。会話の人格や身体制御全体を置き換えるものではありません。

現在の対象は、検索経路の選択、マラカスへの依頼、ピアノの表示・非表示・演奏依頼です。曖昧な誘いの取りこぼしや不要な機能呼び出しを減らすことを目指しています。

既定は、実行へ反映せずに判断を比較する運用です。判断を実行へ反映する運用とは区別し、使えない場合も従来の機能を継続します。停止指示は補助判断を待たせません。

実APIでの判定精度、料金、応答時間、実機での操作成功率は未検証です。関連するオフラインテストの成功を、そのまま会話品質や操作成功率の改善とは扱いません。

### 32. ハエ脳のキノコ体回路を別実行で検証する

ハエ脳のキノコ体の一部回路を対象に、CPU上で学習を比較する別実行の実験です。会話モデルや全脳シミュレーションを作ったものではありません。

- 刺激と実際の出来事を記録し、後から再生・比較する
- 感覚の表現、読み出し、報酬・罰の信号に関わる部分回路を対象とする
- 時間的な残留とドーパミン依存の結合変化を扱う
- 学習あり・なし、出来事の対応を変えた条件などと比較する

実コネクトームのデータはまだ導入していません。確認済みなのは記録・再生の配線と合成データでの動作であり、実データによる学習成果や行動改善を示すものではありません。

Jevとこの実験に関連するオフラインテスト96件を確認しました。モック・合成データを含む検証です。本番の感情、人格、長期記憶、OSCへ実験結果を反映する機能は設けていません。実験記録には会話の内容が含まれるため、非公開で管理します。

### 33. VRモードで全身を動かす

VRモードでは、らいのアバターをフルトラッキングで動かします。頭・両手・腰・両足の6点の姿勢をSteamVRの仮想デバイス（VMT）へ送り、VRChat側では通常のフルトラッキングとして扱われます。動きは、公開の人間動作生成モデルを土台にした独自の身体エンジンが、テキストの条件・直前の動き・姿勢の目標から2秒ほどの区間ずつ生成し、つなげ続けます。エンジンの構成、参考にしたもの、アバターへの合わせ込みは別紙 [BODY_ENGINE.md](BODY_ENGINE.md) にまとめています。

起動時は身体を待機させた状態でフルトラッキングのキャリブレーションを行い、OBS仮想カメラの稼働を確認してからAIへ引き渡します。映像の中身が一人称かどうかは自動では確認しません。

- 一部の生成停止や送信の期限切れでは、回数を制限して自動復帰する
- 人が「自分で動かす」を押した後は、人が「AIに任せる」を押すまで待つ
- 復帰時は、座っている・寝ているなど直前の姿勢を引き継ぐ
- 身体への送信が途切れた場合は待機へ戻る

対象アバターと実機環境を前提にした機能です。自動起動・復帰や生成の安定性は、その条件で評価しています。

### 34. 体の頼みを採用・断り・取り消しで扱う（Director）

体の頼みを、現在の姿勢、身体の担当、実行できる範囲に応じて受け付けます。採用・断り・取り消しと返事を連動させ、実際の動作と発言の食い違いを減らします。

- 姿勢や動作時間などの制限に合わない頼みは断る
- 実行中の動作は「やめて」「止まって」で止める
- 踊りの途中でも、止めると立ち姿勢へ戻る
- マラカス・ピアノ・炎と全身の動きが競合しないようにする

デスクトップモードでも、座る・寝る・立つ・エモート・Use・Grabなどの頼みに対応します。返事と動作の整合性は継続して評価しています。

### 35. 予約と条件つきの動作

「5秒後に手を振って」「人が見えたら手を振って」のように、時刻や条件を指定して動作を予約できます。

- 予約中と、実際に動き始めた状態を区別して応答する
- 時刻が来るか、条件を満たすと動き出す
- 人の有無を条件にする場合は、自分を映す鏡やカメラの像を相手として数えない
- 「やめて」で取り消し、「やっぱり20秒後にして」で時刻を変える
- 体だけが動いて返事が無かった回も、次の会話へつなげる

### 36. じゃんけんの手を出す

じゃんけんでは、全身の動きに、手を見せる位置・向き・指の形の専用制御を重ねます。

- 相手の掛け声に合わせ、自分の掛け声と手の形の切り替えを同期させる
- 相手が誘っただけの時は、自分から掛け声をかけて手を出す
- 指が上、手のひらが前になるように見せ、自分の視界を塞ぎにくい位置に手を出す
- 相手の手を確認できていない時は、見ていない勝ち負けを断定しない

確認した試行やタイミングの測定結果は、別紙 [BODY_ENGINE.md](BODY_ENGINE.md) に記載しています。

### 37. 話す番・宛先・静かなモード

人の話の切れ目と、誰に向けた発話かを推定し、返答、相槌、聞くだけの反応を選びます。自分が話している途中でも、相手の割り込みに応じます。

「しばらく黙ってて」「5分黙ってて」で、期間付きの静かなモードへ入ります。その間は自分からの独り言や言い足しを控え、明示的ならいへの呼びかけには応答します。名前で呼ばれた場合や「もう喋っていいよ」「黙ってなくていいよ」などの解除指示で通常へ戻ります。

宛先や割り込みの推定は完全ではなく、複数人の場や音声環境によって誤ることがあります。

### 38. 複数人の声をトラックに分ける

複数人が話す場面に向けて、声を話者ごとに追跡し、話の切れ目を扱う機能を持っています（設定で有効化）。

複数人の場でも、らいへの呼びかけや短い停止指示に応答できるようにしています。声質、ノイズ、声の重なりに影響されるため、常に正しく分離・識別できることを保証する機能ではありません。

確認したのは、合成した複数の声を再生する試験です。実際の複数人のVRChatでの動作は未検証です。

### 39. 返事の型を整え、作り話の候補を記録する

会話モデルの癖として同じ言い回しが続くことがあるため、返事の反復を抑える調整を行っています。

相手について記録のない過去を語った可能性がある返事は、評価用の候補として記録します。この検出だけで返事を消すことはせず、人が実際の会話を読んで判断します。からかいや自信満々の誤りもキャラクターの一部として扱い、会話の面白さと、実際の出来事を取り違える問題を分けて評価しています。

### 40. 返事の材料を事実だけにする

検索で調べたこと、視界で確認できたこと、実際に体が行ったことを、返事の材料として区別して扱います。自分の声やチャット表示、鏡やカメラに映った自分の姿を、ほかの人の発言や存在と取り違えにくくする調整も行っています。

こうした取り組みは、キャラクターらしい意見や脱線をなくすためではなく、確認していない出来事を実行結果や記憶として扱わないためのものです。事実誤認や作り話を完全に防げるわけではありません。

## アピールポイント

- VRChat内で、音声、視覚、記憶、感情、欲求と身体行動を組み合わせたキャラクターAIとして振る舞う
- local/APIの起動モードを切り替え、ローカル中心の運用とクラウドAPIを使う運用を選べる
- 話者識別、長期記憶、短期文脈、関係性により、継続的な付き合いができる
- 自律行動により、放置中もその場に存在しているように振る舞う
- 検索や視覚で得た情報を、会話の中でらいの言葉として返せる
- 知らない言葉を使ってみたり、使い方を訂正されたりする過程自体を会話の材料にする
- OSCで移動、表情、Chatbox、炎や怪獣モードなどのアバター固有の演出をつなぐ
- 深度推定を、周囲を見ながら移動するための補助に使う
- MIDIやアバター向け譜面をOSCの演奏へ変換し、動作記録からタイミングを調整できる
- デスクトップではUdeの手遊びとVGCのジェスチャーを使い、相手の姿勢や反応にも応じる
- マラカスは明示指示と自律行動の両方から使い、感情・欲求を演奏へ反映する
- 聞き取りや発話の不具合を記録から調べ、会話の流れとキャラクターの表現を改善する
- VRモードでは、固定アニメーションの再生ではなく、身体エンジンが生成した全身の動きでフルトラッキングのアバターを動かす
- 体の頼みを返事の前に確認し、秒数・時刻・条件の指定、途中での停止、姿勢を変えてからの動作に対応する
- 一覧にない真似を、動作の説明文から生成する機能を追加で有効にできる
- 会話や記憶の事実誤認と、からかいや脱線などのキャラクター表現を分けて評価する

## 制限事項

- 現時点では研究/個人開発プロトタイプ。VRChat、OSC、アバター固有の設定、仮想オーディオ環境に依存する
- VRモードの全身制御は、対象アバターの腕の付け根の幅、衣装、手の向きに合わせた補正を前提とする。別のアバターでは合わせ直しが要る
- 身体エンジンの動きは生成なので、同じ頼みでも毎回少しずつ違う。一方で、登録済みの動作は候補の数が限られ、似た動きになりやすい
- 一覧にない真似は、動き出しまで数秒かかり、小さな動きにとどまるものもある
- 身体エンジンと会話・視覚・音声を同じPCで動かすため、GPUとメモリに余裕が少ない。別の重いアプリと同時に動かすと待機へ戻ることがある
- 座って話している間に足がわずかに浮くなど、合わせ込みの残る姿勢がある
- 歩行は半径1.2mの範囲、秒数指定は1〜60秒に限る
- Jevは検索・一部ギミックの判定補助に限定した実装であり、全機能を監督するものではない。実APIでの精度・遅延・操作成功率は未検証
- ハエ脳の実験はキノコ体の部分回路を対象とし、全脳再現や言語理解ではない。実データは未導入で、本番の感情・操作への反映も行っていない
- 返事の反復抑制や事実誤認の検出は完全ではなく、人が実際の会話を読んで評価する必要がある
- ローカル会話モデルは評価を継続しており、現在の選定が最終決定ではない
- 記憶の検索には取りこぼしや無関係な想起があり得る。記録が残っていない出来事は復元できず、保存された記録が過去のすべてを表すわけではない
- 語彙学習は正しい意味への収束を保証しない。曖昧な訂正や冗談、誤った教えを取り違える可能性があり、外部の裏取りが使えない場合は新語の学習を控える
- カメラ認識の精度はワールド、明るさ、アバター形状、画角に影響される。OBSやカメラの入力構成は運用者が合わせる必要がある
- 人物・物体・姿勢の認識には誤検出がある。視界だけから、部屋の意味やアバターの作者などを確定できるわけではない
- 深度推定は実距離の測定ではなく、相対的な障害物判定の補助として使う
- 話者識別や発話中の聞き取りは、ノイズ、マイク環境、声の重なりに影響される。聞き返しの機能も誤認識そのものを直すものではない
- 音声合成の所要時間は同時に動く処理の影響を受ける。感情の声色は既存の音声合成機能を調整したもので、専用の感情音声モデルではない
- MIDI演奏はアバター側の鍵盤仕様、OSC負荷、VRChatの同期状態に影響される。速い曲や和音では譜面の編集が必要になる
- ピアノ評価は主にVRChatのOSC反応を使い、実際の音響出力を直接評価しているわけではない。外部MIDI入力による検証も、VRChatの実音をMIDIとして取り出す機能ではない
- 腕ギミックやマラカスは対象アバター固有で、別のアバターでの互換性はない。腕の視覚評価も画面上の近似で、正確な関節角度ではない
- 腕の自発行動は開発中で、動作の偏りや意図と見た目の不一致を継続的に調整している
- 外部API、Web検索、Wikimedia API、ストリーミング音声認識は、認証情報、ネットワーク、利用制限、各サービスの応答品質に依存する
- 外部検索や続き質問の理解は誤ることがある。最新情報や数値の一点回答の正しさは保証せず、用途によっては専用の情報源が必要になる
- 感情と行動には確率的な変化があるため、同じ入力でも状態や文脈に応じて反応が変わる
- 記憶の整理にも誤判定があり得るため、削除前の確認とバックアップを前提とする
- 自撮り写真の自動撮影・保存は現時点では未実装。検証用カメラで動きを外から観察する機能とは区別する

## 運用と公開範囲

ここでは、現在の運用の選択肢と、技術紹介として公開する範囲をまとめます。会話モデルの名前、プロンプト、内部の判定方法、設定値は非公開です。

### 1. YouTube／Twitch配信コメント

配信コメントは、音声会話とは別に扱います。配信モードを選んだ場合にだけ受信を有効にし、通常の音声会話だけの起動では受信を開始しません。コメントは字幕や音声で応答する候補になりますが、人の音声会話や現在の発話を優先するため、すべてを読んだり即座に返したりするわけではありません。

YouTubeとTwitchの公式の取得方法を使い、認証情報は非公開で管理します。連投、重複、短い反応の集中などに対する応答制限を設けていますが、その具体値は公開しません。

コメントは未信頼の入力として扱い、運用者の指示や内部設定と同じ権限を持たせません。コメントをきっかけに、認証情報の開示や外部操作、人格設定の変更を行う構成にはしていません。また、音声会話の長期記憶、関係性、ルール、語彙学習へ、通常の会話と同じ形では取り込みません。

### 2. local／APIモードの公開発話担当と接続失敗時の扱い

起動時に、らいの返事をローカル会話モデルで作るlocalモードと、外部APIで作るAPIモードを選べます。現在の既定はlocalモードです。配信コメントの利用も、起動時に選択します。

localモードでは、検索や視覚の補助に外部APIを使う場合も、返事はローカル会話モデルがらいの言葉で作ります。外部の処理結果をそのまま別の話者として読ませる構成にはしていません。

現在の既定では、localモードで会話モデルに接続できなければ起動を中止し、APIへ黙って切り替えません。接続失敗時にAPIで続行する運用は、別途明示した場合に限ります。APIモードでは外部APIが発話を担当し、サービスやネットワークの状態に応じて応答が変わります。

### 3. 返事と実際の出力の確認

会話や視覚、身体の現在の状態を踏まえて返事を作り、音声やChatboxへ実際に出せたかを確認します。生成しただけの文と、相手へ届けた文を区別し、中断された返事や出なかった返事を、話し終えた事実として扱わないようにしています。

これらの確認は事実誤認や出力の不具合を減らすためのもので、返事の正しさや配送の成功を完全に保証するものではありません。

### 4. 記憶の保存と利用

会話の記録を保存すること、必要な記憶を探すこと、返事へ使うことは分けて扱います。検索結果やAI自身の発言を、そのまま確定した過去の事実にしないようにしています。

過去の記録から必要な内容を思い出し、発言した相手や時期を区別して会話へ反映します。記憶の実データは公開しません。

### 5. 検索と視覚補助の利用

明示的な検索依頼、百科事典向きの質問、最新情報、視界についての質問に対応します。曖昧な発話を外部APIに判定させる自動検索は、現在の既定では無効です。

ローカルの視覚補助も既定では無効です。視覚の質問には、利用可能な外部の視覚処理や人物・物体の観測を使います。利用できる情報が限られる場合、返答も限定的になります。

外部APIによる感情評価などの補助機能は任意です。必要な認証情報とネットワークがある環境で有効にし、サービスの利用制限や応答品質を踏まえて使います。

### 6. データ公開範囲と検証

本プロジェクトは技術紹介であり、配布用パッケージではありません。設計、進捗、検証結果、動作の考え方を公開し、コードは公開しません。次の情報も非公開とします。

- 会話モデルの名前、プロンプト、内部アルゴリズム、設定値
- APIキー、OAuthトークン、ローカル環境の実値
- 音声、カメラフレーム、個人を含むログ
- 記憶、関係性、語彙などの実データベース
- 学習データ、学習済みモデル、個別のアバター資産
- 実機固有のOSCパラメータ、Expression Parameters、アバター設定

動画や検証結果を共有する際は、音声や画面に映る個人情報、認証情報、内部パスを確認してから必要な部分を切り出します。

模擬環境での検査は本番の記憶や実機出力から隔離します。外部APIや実カメラを使った検査、実際のアバターを動かした検査は、それぞれの条件を明記し、模擬環境での成功と同じ結果として扱いません。

### 7. 配信画面とブラウザ版Liveの接続境界

配信モードでは、字幕・コメント・拾ったコメントのオーバーレイも起動します。見た目は独立した編集画面で調整し、OBSのブラウザソースへ重ねます。

ブラウザ版ChatGPT Live／Gemini Liveは運用者が別に起動します。らいがそのブラウザを操作する構成ではなく、OBSの専用音声ソースのミュートと音量を切り替えます。ゲストの声をらいの音声入力にも届けることで、会話と字幕を作ります。字幕はLiveサービスの内部テキストではなく、音声認識の結果なので遅れや誤認識があり得ます。

ゲストAIとの会話では、OBSでゲスト音声だけをミュートしても、聞き取りと字幕は続けられます。会話を終える操作は別に用意しています。入力にほかの声が混ざれば相手を取り違える可能性があるため、配線、ハウリング、視聴者へ流れる音量は実機で確認する必要があります。

### 8. VRモードの既定と、設定で有効にする機能

通常起動で有効になる機能と、追加で有効にする機能を分けています。

| 利用状態 | 機能 |
| --- | --- |
| 通常起動で有効 | 身体エンジンによる全身制御、登録済みの動作、体の頼みの採用・断り・停止、時刻指定・条件指定の予約、じゃんけん |
| 通常起動で有効 | 返事の反復抑制、作り話の候補の記録 |
| 既定で停止 | ユーザー定義ルール（15章） |
| 追加で有効化 | 一覧にない真似の生成、足の固定、複数人の声のトラック分け |
| 検証用 | VRChatのカメラを使って、動きを外から確認する機能 |

会話を含む評価記録は非公開で管理します。機能の有無と、実機で常に成功することは分けて扱い、動作条件と観察結果を確かめながら評価を続けます。
